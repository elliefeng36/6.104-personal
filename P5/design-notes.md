# User Study Reports and Design Notes

## User 1

The first user completed many tasks quickly and intuitively, including creating a new task, figuring out how to edit or delete tasks, and setting a recurring task. While creating a new task, she instinctively hit enter to make the new task, which worked, but the new task was appended to the bottom of the task list, which made her confused on whether or not it was properly added. She tried to change the sort in order to figure out whether or not the task got added. In the future, it would be helpful to add a signal near the New Task box to indicate that a task was successfully created. I would also add new tasks to the top of the task list, rather than the bottom and sort newly added tasks before older tasks. In general, locating tasks to edit/delete also took more time than optimal, and would have been worse if the task list was significantly longer--a search function might be helpful here. The user also immediately used the sort feature to find the most urgent task and used the filter feature to find tasks under 20 minutes. However, she got stuck trying to remove the filter--she thought that clicking on the box showing "Filtered:" would remove the filter, so maybe adding an X in that box to remove the filter would bridge this gulf in the flow.

## User 2

The second user also completed most of the tasks very quickly and automatically. These tasks included making a new task, figuring out how to edit and delete tasks, adding duration/deadline information, and setting recurring tasks. For the delete dialog, she instinctively clicked through the confirmation dialog, which she said gave her barely any pause in our debrief. The user very quickly understood the minimal information for suggesting tasks, and she nearly automatically clicked "Complete" on the suggested task. Because you currently cannot uncomplete or edit completed tasks, this could be a bad situation if someone were to complete a task on accident or misclick. Lastly, this user did not use the sort feature to find the most urgent task or list tasks under 20 minutes, possibly because the prepopulated task list was fairly short (around 10 tasks). She quickly figured out how to use these features after I asked a followup question along the lines of "what if there were a hundred tasks?", and in our debrief, she said that while she saw the features, she didn't see the need to use them because it was easier to answer these questions off of sight alone.

## Design Issues

**Difficulty in removing filters** (Linguistic, Major): The only way to remove a filter is by deleting everything that is typed in the filter box and "reapplying" the new filter, or by refreshing the page, which is not a great solution. This is very confusing to users and can block the flow of using the app. One method of fixing this would be to add an X button to the "Filtered: " box in order to remove the filter, which is fairly intuitive, and which the user tried to do.

**Unintuitive task order** (Linguistic, Moderate): When sorting by task added order, the most recently created tasks are sorted to the bottom, which is unintuitive and may confuse users who are expecting to see their newly created task at the top of the task list. This is easily fixed by reversing the order in which tasks are displayed to be newest first.

**Unable to search tasks** (Conceptual, Moderate): There is no way to search tasks by task name. While this is fine for short task lists, if a task list gets unwieldy (which it often does), it's extremely difficult to find tasks directly in order to complete, edit, or delete them. We could fix this by adding a searchTasks concept to the app.

**Unable to modify tasks** (Conceptual, Major): Once a task is completed, there is no way to uncomplete, edit, or delete the task. So, if a user were to accidentally complete a task, there would be no way to fix this error. We could fix this by changing the taskListing concept to allow completed tasks to be modified.
